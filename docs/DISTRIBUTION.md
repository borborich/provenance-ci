# Distribution

No cold outreach, enterprise demo, manual onboarding, or buyer contact is part
of the plan.

## Launch sequence

1. Verify name/trademark and terminology.
2. Publish a public source repository with immutable release artifact,
   checksums, fixture evidence, security policy, and five-minute quickstart.
3. Publish the GitHub Action after owner approval and required account/legal
   steps.
4. Add a README badge and copyable sample workflows.
5. Publish an indexable static documentation site with exact problem-oriented
   guides, stable canonical URLs, a sitemap, and explicit crawler access.
6. Publish controlled, reproducible compatibility pages only from versioned
   fixtures and exact platform configurations.
7. Consider a no-registration public URL scanner only after local usage proves
   the job and its separate security gate passes.

## Organic channels

- GitHub repository search and topics;
- GitHub Actions Marketplace;
- a static GitHub Pages reference site with no analytics or hosted scanner;
- technical documentation for exact failure/status queries;
- sample workflows and badges in users' repositories;
- opt-in shareable evidence reports in a future stage;
- controlled WordPress/CDN compatibility matrix;
- a WordPress plugin only after a usage gate.

Search and AI-assistant discovery use the same evidence discipline as the
product. Pages lead with a direct answer, name the tested versions and supplied
checkpoints, link to reproducible fixtures, and state limitations. The project
does not create scaled low-value search pages, manufacture community questions,
or imply that crawler access guarantees indexing, citation, or recommendation.

The static site may allow search-oriented crawlers such as Googlebot, Bingbot,
OAI-SearchBot, Claude-SearchBot, and PerplexityBot. Model-training crawlers are
a separate policy choice and are not required for current search visibility.

## Claims discipline

Public copy says “valid Content Credential,” “validation failed,” “credential
absent,” or “first observed break between A and B.” It never says authentic,
fake, C2PA certified/compliant/conformant, or affiliated.

The Content Credentials icon and C2PA/CAI vendor marks are not used as the
project logo or Marketplace branding.
