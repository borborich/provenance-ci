How to find where C2PA Content Credentials are first observed to break

Validate an ordered list of checkpoints—not just the source and final URL. Provenance CI compares every adjacent pair and reports the first supplied interval where credentials disappear, fail validation, or no longer have exact-byte or validated declared-parent continuity.

Tested with Provenance CI 0.1.1 C2PA SDK 0.90.3 JPEG Updated 2026-07-29

Short answer

Add checkpoints immediately before and after the systems you want to observe, such as a build, CMS export, image optimizer, origin, and CDN. A break between build and production means only that this is the first supplied interval where the change was observed. It does not identify an unobserved CMS, optimizer, or CDN as the cause.

Run the committed example

The repository includes a signed source JPEG, a valid declared C2PA derivative, and a production fixture without a manifest. Clone the immutable release and run the versioned configuration: 

git clone --branch v0.1.1 --depth 1 \
  https://github.com/borborich/provenance-ci.git
cd provenance-ci

cargo run --release --locked -- \
  --config examples/provenance-ci.yml \
  --output provenance-ci-result.json \
  --markdown provenance-ci-summary.md

This intentional regression returns exit code 2 because the configured policy fails. Exit code 3 is reserved for inconclusive infrastructure, acquisition, or configuration failures.

The ordered checkpoint configuration

version: 1

trust:
  id: not-configured

checks:
  - id: signed-source-to-derived
    checkpoints:
      - name: source
        path: ../fixtures/official/C.jpg
      - name: build
        path: ../fixtures/official/declared_derivative.jpg
      - name: production
        path: ../fixtures/official/no_manifest.jpg
    policy:
      requireCredential: true
      requireValidBinding: true
      continuity: exact-or-declared-derivative
      onInconclusive: warn
Trust is deliberately not checked in this portable example. To evaluate trust, supply a pinned local PEM snapshot and record its immutable identifier. Without that file, the result is not_checked, not untrusted.

Tool statement

First observed break occurred between checkpoint 'build' and checkpoint 'production'.

The build output is not byte-identical to the source, but it contains a valid current manifest and validated parent evidence referring to the prior active manifest. It is therefore reported as a declared C2PA derivative, not as a continuity break. The production fixture is the first supplied checkpoint where the credential is absent.

Inspect the versioned configuration and fixture provenance used for this result.

Apply the pattern to a real publishing pipeline

  1. Save the signed source asset as a local path checkpoint.
  2. Add a local checkpoint after every build or image-generation stage you control.
  3. Expose public HTTPS checkpoint URLs for the origin and delivered asset where appropriate.
  4. Name checkpoints after observed locations, not presumed causes.
  5. Run the same ordered configuration after relevant pipeline changes. 
checks:
  - id: homepage-hero
    checkpoints:
      - name: signed-source
        path: assets/hero.jpg
      - name: build-output
        path: dist/hero.jpg
      - name: origin
        url: https://origin.example.com/hero.jpg
      - name: delivered
        url: https://www.example.com/images/hero.jpg
    policy:
      requireCredential: true
      requireValidBinding: true
      continuity: exact-or-declared-derivative
      onInconclusive: warn

URL checkpoints accept public HTTPS on port 443 only and apply destination, redirect, content-type, body-size, and timeout controls. Query strings are not persisted in results.

What the result does not prove

A first observed break is an interval, not a root-cause claim. If the only supplied checkpoints are build and production, the tool cannot distinguish an intervening CMS, optimizer, origin process, or CDN behavior. Add controlled intermediate checkpoints to narrow that interval.
  • Credential absence does not prove that content is false, manipulated, or AI-generated.
  • Valid cryptographic binding does not establish authorship, copyright, or content truth.
  • A changed file can be a valid declared derivative.
  • Remote manifests and soft-binding recovery are not evaluated in the MVP.
  • Perceptual similarity is not treated as C2PA continuity evidence.
