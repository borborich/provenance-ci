GitHub Actions quickstart

Validate C2PA Content Credentials across publishing checkpoints

Add one versioned YAML file and one Action step. Provenance CI validates ordered local-path and public-HTTPS JPEG checkpoints, reports the first observed break, and keeps user assets on the caller's runner.

Provenance CI 0.1.1 GitHub-hosted or self-hosted runner Updated 2026-07-29

1. Add the checkpoint policy

Create provenance-ci.yml in your repository. Paths are resolved relative to this configuration file. 

version: 1

checks:
  - id: homepage-hero
    checkpoints:
      - name: source
        path: assets/hero.jpg
      - name: build
        path: dist/hero.jpg
      - name: production
        url: https://example.com/images/hero.jpg
    policy:
      requireCredential: true
      requireValidBinding: true
      requireTrusted: false
      continuity: exact-or-declared-derivative
      onInconclusive: warn

The ordered list defines what the tool can observe. If a break is first seen between build and production, the result identifies only that interval.

2. Add the workflow step

name: C2PA checkpoint validation

on:
  pull_request:
  push:
    branches:
      - main

permissions:
  contents: read

jobs:
  provenance:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: Check out repository
        uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd

      - name: Validate C2PA Content Credentials
        uses: borborich/provenance-ci@v0.1.1
        with:
          config: provenance-ci.yml

The release tag is immutable. For the strongest supply-chain pinning, resolve v0.1.1 and use its reviewed full commit SHA. Direct Action dependencies inside Provenance CI are also pinned by full SHA.

3. Interpret the result

Exit Meaning
0 Configured policy passed or produced configured warnings.
2 Deterministic policy failure.
3 Infrastructure, acquisition, configuration, or unresolved inconclusive failure.

Every checkpoint result records byte SHA-256, media type, size, timestamp, SDK version, trust configuration, raw validation codes, evidence, and limitations. URL results include the final redacted URL where applicable.

Action output is evidence, not an authenticity verdict. Presence, cryptographic validation, trust, continuity, and configured policy remain separate fields.

Artifact and privacy controls

By default, the Action uploads the versioned JSON result as a GitHub Actions artifact with 14-day retention. It does not upload raw user assets to Provenance CI and the project operates no backend, analytics endpoint, or telemetry collector. 

- name: Validate without uploading the JSON artifact
  uses: borborich/provenance-ci@v0.1.1
  with:
    config: provenance-ci.yml
    upload-artifact: "false"

The Job Summary and annotations still expose checkpoint names and validation outcomes to users who can read the workflow run. Choose non-sensitive checkpoint names and review the privacy and data-flow documentation.

Public URL checkpoints

URL checkpoints accept public HTTPS on port 443 or implicit port 443 only. Acquisition rejects credentials, private or reserved destinations, redirects to disallowed destinations, non-JPEG content, oversized bodies, and excessive redirects.

  • The user-declared top-level asset URL is the only remote content acquired.
  • SDK-controlled remote manifest and external assertion retrieval is disabled.
  • URL query strings are not persisted in results.
  • Trust material is never downloaded implicitly.

Optional pinned trust snapshot

Trust is not equivalent to cryptographic validation. To evaluate it, pin a local PEM snapshot and record an immutable identifier: 

trust:
  anchorsPath: ./C2PA-TRUST-LIST.pem
  id: https://github.com/c2pa-org/conformance-public/commit/<commit>

The result records the PEM SHA-256. Without anchorsPath, trust is not_checked; the tool does not silently call that state untrusted.
