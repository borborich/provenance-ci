Scope and limitations

Evidence at supplied checkpoints—not a truth or root-cause oracle

Provenance CI is a local JPEG validation core, CLI, and GitHub Action. Its narrow scope is deliberate: explicit evidence, controlled network behavior, and honest inconclusive results.

Version 0.1.1 JPEG only Updated 2026-07-29

What the MVP evaluates

  • Ordered local JPEG paths and public HTTPS JPEG checkpoints.
  • Credential presence through the official CAI C2PA Rust SDK.
  • Cryptographic validation and raw validation codes.
  • Optional trust against an explicitly supplied local PEM snapshot.
  • Exact bytes or validated declared parent lineage between adjacent checkpoints.
  • A versioned repository policy mapped to stable exit codes.

What the result cannot establish

Do not use this tool as an authenticity label. It does not determine whether an image is true, authentic, human-created, AI-generated, unmanipulated, correctly copyrighted, or signed by an entity that deserves trust.
  • A present credential is not automatically valid.
  • A valid credential is not automatically trusted.
  • A trusted signer does not make every assertion factually true.
  • Credential absence does not prove manipulation or AI generation.
  • Byte inequality or perceptual similarity does not decide declared continuity.

First observed interval semantics

The tool compares adjacent checkpoints in the exact user-supplied order. It reports the first interval where the available evidence changes in a policy-relevant way.

Permitted claim

“First observed break occurred between checkpoint build and checkpoint production.”

Unsupported claim without more evidence

“The CDN stripped the credential.”

Naming a breaking component requires a supplied intermediate checkpoint or a controlled integration test that isolates that component.

Network and format limits

  • JPEG is the only supported media format in the MVP.
  • Remote manifest references are reported but not fetched or evaluated.
  • External assertions, remote ingredients, icons, and soft-binding recovery are not fetched.
  • SDK-controlled OCSP and arbitrary remote retrieval are disabled.
  • Public URL checkpoints are restricted to HTTPS on port 443 with destination and redirect checks.
  • The SDK is pre-1.0 and implements a subset of C2PA 2.4.

Privacy and operations

The project operates no hosted scanner, account system, analytics endpoint, telemetry collector, or signing service. The GitHub Action runs on the caller's runner. By default it uploads only the versioned JSON result as a GitHub Actions artifact; this can be disabled.

URL query strings, raw assets, manifest bodies, EXIF data, and credentials are not logged by the tool. Checkpoint names and configured local path strings can appear in results, so users should avoid sensitive naming.

Project status

The project is independent and uses the official CAI SDK behind an adapter. It is not C2PA certified, compliant, conformant, affiliated, or endorsed, and it does not use C2PA, CAI, Adobe, or Content Credentials brand assets as its logo.
